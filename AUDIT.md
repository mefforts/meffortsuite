# MeffortSuite 1.1.4g release audit

This update repairs pole-equipped double-right-click fishing and delayed/indexed banker dialogues, and adds optional quiet fishing audio under Professions. Quiet audio is off by default per character. The existing all-quality loot display and native red range-color safeguards remain unchanged.

Fishing accepts native camera evidence when world focus is hidden. It installs its private secure binding after the first release, before the second press. UI clicks, expiry, combat, loot, equipment changes and disabled features cancel the gesture. Restricted combat cleanup also disables a preselected cast button. The ranged controller clears its retained private state attribute on unregister so it can rebind after a pole is removed. Shared input libraries and wand macros remain unchanged.

Service shortcuts accept native option indexes when IDs are hidden, tolerate an absent zero-valued icon override and make one bounded delayed menu check. Dedicated Orgrimmar shortcuts share the same selection guards, including with general shortcuts disabled. Shift bypass persists through deferred updates. Cost, confirmation, quest, combat and ambiguous-menu guards remain in place for general shortcuts.

Quiet audio changes only music, ambience and dialogue channel volumes while Fishing is channeling with a pole equipped. Effects and master volume remain unchanged; this does not isolate the bite. Original volumes are recorded before changes. Restoration only updates channels still at the owned zero value, retaining manual changes and retrying failed restores from validated recovery data. A hard crash cannot guarantee that new SavedVariables were persisted. The module uses events without idle polling, and master disable restores audio immediately.

All shipped source, data, XML, metadata and documentation were scanned for model names, prompt exchanges, transcript markers and draft labels. Comments explain API contracts, protected ownership, ordering, localization, timing or safe item transfers. License and source-data attribution notices remain byte-identical to 1.1.4f.
