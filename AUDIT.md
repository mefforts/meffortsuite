# MeffortSuite 1.1.4c release audit

A supplied client report records 80 ADDON_ACTION_BLOCKED events during combat with action UNKNOWN(), no open NPC/bank/profession interface, and no standalone MeffortWand. It establishes repeated native protection failures, but does not identify the original API or taint source. No definite root-cause attribution is made from that report.

Target-distance polling now excludes CheckInteractDistance from combat, matching the existing item-range guard. Range queries and camera start/stop calls use a private suite wrapper that records the active call while retaining normal API dispatch. A native blocked event during that call suspends only the corresponding operation and combat condition for the UI session. There are no replacements or hooks on global client APIs, and no saved feature preference is disabled. Supported combat spell probes remain available; unavailable or refused results remain unknown and never become a definite out-of-range warning.

Camera start respects explicit failure results and the applied input mode. Blocked release stops repeated frame-driven attempts and retains pending cleanup for a retry after combat. Macro actions and the secure driver remain separate from the camera helper.

Reports retain the first bounded event stack for an entry, aggregate duplicate events, and capture the wrapped call where available. Calls observed within one second of a deferred event are explicitly labelled correlation only and are not used to suspend an unproven source. The existing 16-entry native-event and 8-entry Lua-error limits remain. Stack captures are limited to six lines, with 180 characters per line. The explicit copy window allows 50,000 characters to retain the bounded report. Exports include the applied ranged mode, camera cleanup state, and saved range-warning preference. No automatic popup or transmission is added.

Twelve new regression tests simulate native blocks that do not raise Lua exceptions, operation/combat isolation, 80 attempted repeats, scope cleanup, unknown-action stack limits, unavailable/secret stack data, delayed-event correlation, range guards, supported range behavior, and camera cleanup. These tests do not establish real Forever taint behavior or event timing. Live verification and a new report remain necessary if the failure recurs.

Dialogue gutter state now validates rendered icon and caption bounds as well as anchors. A horizontal layout change while an inset is active no longer becomes a new native baseline. Owned geometry is restored and the affected row's label is paused until the next conversation; other rows and keyboard shortcuts remain available. Close/disable cleanup also removes drift while the label-owned width is still present. An externally replaced position and width remain under the external owner's control. Initial placements that move content beyond the expected single inset are rolled back immediately. Pixel rounding within one unit is tolerated in rendered bounds checks.

Ten focused tests cover late caption and icon drift, implicit visual displacement without changed anchors, native width reset, immediate invalid placement, close-before-refresh cleanup, new-dialogue recovery, unsupported initial spacing, external layout ownership, and small pixel rounding. Eight regression scenarios expose missing guards in the prior 1.1.4a build under the same simulated API conditions. Native rendering remains a separate client check.

Login announcements now run once per login or UI reload rather than only on first installation. They use the existing chat message function and include version, master status, and the settings paths. A saved account-wide Show login message preference defaults to enabled and is available in both the native Options canvas and the suite About page. No notification popup is created.

The native AddOns category uses RegisterCanvasLayoutCategory and RegisterAddOnCategory on Forever's Interface 16001 Settings API, with a legacy InterfaceOptions_AddCategory fallback. Registration waits for an available API through load/login events and unregisters its events after success. The page uses native button and checkbox templates, opens the existing feature launcher, and uses the native Close method so unapplied settings retain Blizzard's confirmation flow. It does not replace native methods, reparent protected controls, or poll.

The banking inclusion list is additive to ordinary crafting-reagent deposits and uses the same exact-name or numeric-ID format as exclusions. Keep in bags wins over both inclusion forms. The list defaults to empty and is stored per character; existing preferences and exclusions are retained.

The bank controller uses the selective transfer path whenever either list has entries. Missing selective capabilities or unavailable character-bank access refuse the operation; the code does not fall back to a bulk reagent request. Native auto-deposit support is checked for bulk requests, while manual selective transfers use character-bank access checks where available. The automatic coordinator waits for selective completion and performs bank sorting afterward, including long batches.

Eligibility is rechecked before each pickup. An explicit inclusion may override an absent or false reagent flag, but still requires a known item name and valid stack limit. Exclusions are checked first. Partial-stack splitting, destination readback, source/destination count confirmation, compatible-source restoration, and bounded retries remain in place. The bank still enforces its own item restrictions.

The Bags settings page labels the additional list Also deposit and explains exclusion priority, character scope, and list-change cancellation. Both fields retain independent drafts. Deposit items now and /msuite bank now use the same selection. Commands, status messages, and documentation are written for players without conversational instructions or prompt remnants.

The 1.1.4 bank inclusion list, 1.1.3 dialogue changes and blocked-action diagnostics are retained. Unrelated Lua modules, spell data, textures, bindings, and licensing are unchanged. The package builder validates versions, the explicit TOC manifest, residue, permissions, and ZIP integrity.

Automated inventory tests simulate slot updates and transfer ordering; they do not emulate engine protection, server permission decisions, or live client timing. In-game checks are listed in VALIDATION.md. This archive is prepared for testing and is not submitted to CurseForge or published as a cloud environment.
