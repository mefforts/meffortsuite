# MeffortSuite 1.1.6 feature audit

This review covers all 21 shipped Lua modules, bindings, player documentation, metadata and packaged assets. It inventories every documented feature and mode, reviews lifecycle and shared ownership, and runs the full regression suite. It does not claim exhaustive coverage of every possible client state or third-party addon combination. Automated checks simulate WoW APIs; actual Forever input dispatch, taint, rendering and server responses require client checks.

## Confirmed findings and fixes

1. **Physical ranged attacks could retain the old spell during combat.** Equipment events deferred macro rewrites until combat ended. Warriors and rogues now use one verified macro with native equipped-weapon conditions for Throw, Shoot Bow, Shoot Gun and Shoot Crossbow. Weapon swaps change selection without editing a macro or protected attributes during combat.
2. **Shared library versions could disagree about weapon-specific macros.** Suite supplied version 6 while standalone Wand supplied version 10. The newer manager could preserve a separate macro per spell and exhaust the two reserved names. Suite now supplies a compatible version 11, upgrades known tables in place, and recognizes existing generated physical macros for migration to the single weapon-aware macro. The actual standalone Wand modes, including its sequence variant, remain supported in both load orders.
3. **Implicit cleanup could modify/delete macros without an explicit request.** The Suite manager now adopts the stricter ownership and explicit-only cleanup implementation. Account/custom macros are preserved; unchanged macros are not rewritten; missing APIs, full slots, malformed counts, failed verification and failed deletion stop safely. Explicit cleanup retains the requested attack/sequence variant and refreshes peers after reindexing. A macro body that cannot be constructed is never used as justification for deletion.
4. **A user-edited macro could remain bound until a deferred refresh.** The attack type is now withdrawn immediately outside combat when an external macro update arrives. Addon-owned writes are guarded against reentrant refreshes. Recovery uses verified contents and preserves the edited macro.
5. **Unarmed or unsuitable weapon states could still intercept input.** Native equipped-weapon state conditions now gate each supported class and activation mode. Unsupported weapons leave normal input active. Missing item-cache data no longer selects Throw as a fallback. Ranged initialization after a combat reload waits until combat ends and then retries.
6. **Single-click fishing installed its binding after mouse-down.** It now prepares its private binding before the first press. Known UI clicks cancel a preselected action; it rearms after release without casting or idle polling. Channel/loot completion, equipment changes, mode changes and combat restore or withdraw readiness as appropriate. Double-click remains the default and keeps its transient between-click binding.
7. **Dedicated flight shortcuts did not share all indexed/delayed-menu guards.** They now use the common service selector, including hidden IDs, order indexes, cost/confirmation checks, delayed data, refresh events and persistent Shift bypass. Bank and flight selection markers are set before dispatch so nested close/open events cannot leave a stale selection for the next visit.
8. **Bank state could change between pickup and placement.** The selective coordinator now rechecks access, master/combat/cancellation state and destination identity/count after pickup. It restores only its own matching cursor item to a compatible original slot; a foreign cursor item is left for manual handling. No stale destination is clicked. Source and destination stack counts must be readable positive finite integers; unknown counts are not guessed as one.
9. **Invalid monetary values and explicit refusals could be treated as requests.** Merchant amounts now require readable nonnegative finite integers. Native sale, repair, deposit and bank-sort refusals are no longer marked as successful requests. Retry windows and visit-generation guards remain bounded.
10. **Invalid native map positions could reach arrow geometry.** Non-finite/out-of-bounds pins, non-finite world/player positions, invalid facing/radius and invalid minimap dimensions are rejected before geometry updates. Normal zone lookup and native waypoint ownership remain intact.

## Automated result

All 32 regression scripts pass: 390 unit-test methods plus five tooltip script checks. Parameterized class/weapon/mode and failure scenarios run inside several methods. Lua 5.1, manifests, archive reproducibility and full addon loading are also checked.

## Performance and ownership review

Weapon selection uses native macro/state conditions rather than new range/item polling. Macro acquisition is guarded against synchronous update recursion, preserves existing indexes when unchanged, and only cleans duplicates on explicit request. Single-click fishing readiness leaves no idle OnUpdate; double-click tracking expires. Loot floats have a bounded pool/history and stop polling after work completes. Quest labels stop when their menu hides; shared caches use weak ownership where applicable. Merchant/bank callbacks use generation checks and finite retry windows. Waypoint polling retains its existing bounded cadence; the audit adds value validation rather than extra work.

## Client checks before broad release

1. On a warrior and rogue, enable right-click and Shift modes. Swap Throw, Bow, Gun and Crossbow repeatedly outside combat and in combat. Verify the correct native action, no extra macros and native behavior for missing ammo/training, minimum range and unusable weapons.
2. Repeat with standalone MeffortWand installed/enabled/disabled, its normal and sequence modes on appropriate classes, a fishing pole, existing custom/account macros and an explicit cleanup. Test combat reload and manual macro edits outside combat.
3. Try single fishing immediately after equipping a pole, after UI/left clicks, after catching/canceling a cast and after combat. Repeat default double mode, held camera turns, UI/bobber clicks, lag and modifiers. No timer should cast a spell without a new player input.
4. Verify indexed/delayed bank and taxi menus with general shortcuts on/off, holding/releasing Shift and making consecutive visits. Try a vendor with quests or confirmations to confirm it stays guarded.
5. With inexpensive items, test filtered deposits while closing the bank, moving stacks, changing filters or interacting with another bag addon. Confirm no item swap, correct restoration or a clear occupied-cursor status. Check repair/sale refusals and native map transitions.
6. Follow VALIDATION.md for the remaining feature-specific client cases: tooltip/bar red warnings, dialogue layout/scrolling, audio restoration, loot receipts/value, enchanting confirmation, range estimates, tracked buffs, small-screen settings and log copy/paste.

Automated results establish the covered control flow. They cannot certify every native taint path, server event order, rendered layout or third-party interaction. Any further blocked event should be exported before reload with the 1.1.5 support instructions retained in this release.
